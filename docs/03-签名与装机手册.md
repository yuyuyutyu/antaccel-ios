# 03 · p12 签名与装机手册

## 1. 三个文件,一条命

| 文件 | 是什么 | 缺了会怎样 |
|---|---|---|
| `cert.p12` | 证书 + 私钥(Apple 签发),口令保护 | 签不了,报 `no identity found` |
| `profile.mobileprovision` | 描述文件:授权哪个 Bundle ID、哪台设备、哪些 entitlement | 装不上,报 `ApplicationVerificationFailed` 或装完秒退 |
| `*.ipa` | Payload/App.app 的 zip | —— |

**只有 p12 是签不出能装的包的。** 网上那些"只给 p12 就能装"的说法,背后都有一份由证书团队签发的描述文件在配套使用(企业 In-House 证书通常自带长效描述文件)。

## 2. 证书类型速查

| 类型 | Subject 特征 | 设备限制 | 有效期 | 装机方式 |
|---|---|---|---|---|
| 个人开发者 | `Apple Development: xxx (TEAMID)` | 100 台 UDID | 1 年(证书)/ 7 天(免费号) | 数据线 / Sideloadly |
| 公司开发者(Ad Hoc) | `Apple Distribution` + In-House=False | 100 台 UDID | 1 年 | 数据线 / OTA |
| **企业 In-House** | `Apple Distribution` / `iPhone Distribution: 公司名` | **不限** | 1 年(证书),描述文件可能 3 年 | OTA 链接 / 爱思助手 |
| App Store | `Apple Distribution` | 只能走商店 | 1 年 | 不能侧载 |

判断方法:跑 `resign/inspect_signing.ps1`,看 `ProvisionsAllDevices` 是 `true` 还是列出了 UDID。

## 3. 装机的四道坎

### 3.1 包名不匹配

    Info.plist:  CFBundleIdentifier = com.arknet.shell
    描述文件:     application-identifier = ABCD123456.com.arknet.shell

不匹配 -> 安装器直接拒。本包的处理:构建脚本从描述文件里**反读**包名,再用 `-b` / `plutil -replace` 写进 Info.plist,保证两边永远一致。

### 3.2 entitlements 不匹配

签名时注入的 entitlements 必须是描述文件 `Entitlements` 字典的子集。本壳不申请任何特殊资质(不用 VPN 扩展、不用推送、不用 iCloud),所以几乎任何描述文件都能签。

### 3.3 设备不在列表

Ad Hoc/开发包:目标 iPhone 的 UDID 必须在 `ProvisionedDevices` 里。查 UDID:连电脑 -> 爱思助手"设备信息",或 Xcode `Devices and Simulators`。

### 3.4 证书未信任 / 掉了

企业包首次打开会提示"未受信任的企业级开发者":

    设置 -> 通用 -> VPN与设备管理(or 描述文件与设备管理)-> 找到公司名 -> 信任

iOS 17 之后还多一条:iCloud 私密代理/开发者模式不需要,但"设备管理"入口位置随大版本有位移。

## 4. 装完闪退的 9 个真凶(按概率排序)

| # | 现象 | 真凶 | 处置 |
|---|---|---|---|
| 1 | 点开就退,无任何提示 | 描述文件过期 | 重新取描述文件重签 |
| 2 | 点开就退 | Bundle ID 与描述文件不一致 | 跑 `inspect_signing.ps1` 对齐 |
| 3 | 点开就退 | 证书 revocation / 掉签 | 换证书重签 |
| 4 | 白屏 3 秒后退 | 启动图缺失 + 部署版本过高 | 本包已带 `LaunchScreen` 与 iOS13 目标 |
| 5 | 装都装不上 | 设备不在 `ProvisionedDevices` | 加 UDID 重出描述文件 |
| 6 | 装完图标灰,提示"无法验证 App" | 网络校验失败(企业证书需要首次联网) | 换网络/关代理重试 |
| 7 | 部分机型闪退 | 只编了 x86_64 或 armv7 | 本包 `ARCHS=arm64` 全设备覆盖 |
| 8 | 打开后马上退,日志有 `dyld` 报错 | 签名时漏签 Framework/AppEx | 脚本逐层 `codesign`;第三方包用 `--deep` 复查 |
| 9 | 提示"App 需要更新" | 描述文件 `ExpirationDate` 已过 | 同上,重取 |

## 5. 自己动手的验收清单(逐条打勾)

    [ ] 1. inspect_signing.ps1 跑通,TeamID 一致、未过期、含私钥
    [ ] 2. 描述文件 ProisionsAllDevices=true,或目标 UDID 在列表里
    [ ] 3. IPA 内含 Payload/*.app/Info.plist
    [ ] 4. IPA 内含 Payload/*.app/_CodeSignature/CodeResources
    [ ] 5. IPA 内含 Payload/*.app/embedded.mobileprovision
    [ ] 6. Info.plist 的 CFBundleIdentifier 与描述文件一致
    [ ] 7. 二进制是 arm64(用 `file Payload/*.app/AntiAccel` 或 CFF Explorer 看)
    [ ] 8. 装机后图标正常,首启 3 秒内进首页
    [ ] 9. 首页能列出热门站点,点进去能打开网页
    [ ] 10. 导航页(WebView)能渲染,点"调用原生 toast"能弹窗(桥接通)
    [ ] 11. 我的页能显示版本与 Bundle ID

## 6. 分发方式

- **数据线**:爱思助手 -> 应用 -> 安装本地 IPA;或 Sideloadly。
- **OTA(企业证书)**:把 `AntiAccel.ipa` 和 `manifest.plist` 放同一 HTTPS 目录,分发链接写 `itms-services://?action=download-manifest&url=https://.../manifest.plist`。manifest.plist 模板见 `ios/manifest-example.plist`。
- **TestFlight**:需要 App Store Connect 账号,上传需 `altool/notarytool` 与正式证书。
